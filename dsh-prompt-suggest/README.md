# dsh-prompt-suggest

输入框底部工具行的提示词建议按钮：一键生成下一条指令建议；已有草稿时润色草稿并在可编辑卡片中确认后替换。

## 功能

- **生成建议**（输入框为空时点击按钮）：基于最近一轮对话生成一条指令建议，直接填入输入框。
- **润色草稿**（输入框有草稿时点击按钮）：把当前草稿交给模型润色，结果先弹进可编辑卡片——`Ctrl+Enter`（或点"替换草稿"）保存替换，`Esc` / 取消丢弃不动原文。
- 默认跟随当前会话的模型；在**设置 → 提示词建议**里可以固定用某个模型、单独选思考强度、自定义两个模式的提示词模板，并调整长度上限。

## 位置

- 按钮：`conversation.input.right`（composer 工具行、提交按钮前的紧凑控件区；会话内才渲染）。
- 编辑卡片：`shell.overlay`（frame 顶层）。
- 设置页：`settings.section`（DSH 设置页里的「提示词建议」分区）。

## 数据通道

client 面点击按钮后 `POST /plugins/prompt-suggest/generate`：

```json
{ "sessionId": "...", "draft": "...", "provider": "...", "model": "...", "reasoningEffort": "..." }
```

host 面流程：`sessionQuery.readSurface(sessionId)` 取最近一轮 user/assistant 文本（user 尾 1500 / assistant 尾 3000 字符）→ 用模板组装 meta-prompt → `llm.prepareCall` + `stream` 一次辅助调用（20s 超时）→ 返回原始文本。草稿超过草稿上限时直接拒绝（HTTP 413），不截断。

设置页另有三条路由：

| 路由 | 作用 | 调用模型 |
|---|---|---|
| `POST /plugins/prompt-suggest/preview` | 用编辑框内容组装提示词并返回全文 | 否 |
| `POST /plugins/prompt-suggest/trial` | 用编辑框内容真实调用一次模型，结果只显示在设置页 | 是 |
| `POST /plugins/prompt-suggest/settings` | 保存偏好，先校验再落盘 | 否 |

预览与试跑读取编辑框的当前内容，**不需要先保存**；正常按钮只使用已保存的模板。预览和试跑的长度校验只受硬上限 32000 约束，不受已保存的模板上限约束——否则调高上限但还没保存时，预览仍会被旧上限卡住。

## 提示词模板

整段 meta-prompt（含输出规则与数据块）都是模板，可在设置页修改。素材通过占位符注入，写成 `{{name}}`：

| 占位符 | 含义 | 适用模式 |
|---|---|---|
| `{{userText}}` | 最近一条用户消息（尾截断 1500 字符，空则为「（无）」） | 两者都必需 |
| `{{assistantText}}` | 代理最近一次回复（尾截断 3000 字符，空则为「（无）」） | 两者都必需 |
| `{{draft}}` | 草稿（整段送入，不截断） | polish 必需 |
| `{{polishCap}}` | 润色长度上限的数字，由代码替换 | polish 必需 |

保存时校验：缺少必需占位符、出现当前模式不允许的占位符、或写坏了花括号，都会拒绝保存并列出问题。留空或只含空白的模板等同于"恢复默认"，保存为空串，之后内置默认更新时仍能跟随。

内置默认模板的设计：

- **suggest** 先给「该推进什么」的判据（待确认项 → 验证收尾 → 新动作），再给写法（一行、≤60 字、动词开头、不复述上一轮），并配一组正反例。
- **polish** 先判力度再动笔，分三档：信息已足 → 只润色；只表达模糊意图 → 用对话补全；本身是问句 → 改写成可执行任务。草稿已足够清楚时允许原样输出。
- 对话与草稿用三引号围成数据块，降低「历史文本被当成指令」的概率。

## 输出不做清洗

模型返回什么就是什么：不剥引号、不剥代码围栏、不取首行、不截断、不去重。唯一的输出校验是**空输出报错**（写入诊断日志，页面给通用文案）。两种输出都先呈现给用户再生效：suggest 填进输入框，用户发送前可见可改；polish 进入确认卡，用户按 Ctrl+Enter 才替换。

因此输出格式完全由模板决定。模板写坏时，多行或前言会直接出现在输入框里。用预览和试跑来检查。

## 长度上限

| 项 | 默认 | 说明 |
|---|---|---|
| 草稿上限 | 8000 | 润色时整段草稿的最大字符数，超出则拒绝（413），不截断 |
| 模板上限 | 8000 | 自定义提示词的最大字符数 |

两项都可填 1 到 32000 的整数，不设下限。草稿上限调大后，超出模型上下文窗口的请求会由模型调用失败返回 502，详情见 `~/.dsh/storages/prompt-suggest/last-error.json`。

润色的长度靶子 `polishCap(draft) = min(16000, max(600, 原文 × 2))` 只作为 `{{polishCap}}` 的数字写进提示词，host 不据此截断结果。

## 设置

**设置 → 提示词建议**，存在 `~/.dsh/storages/prompt-suggest/settings.json`：

| 项 | 默认 | 说明 |
|---|---|---|
| 用哪个模型 | 跟随当前会话 | 固定后按钮只用这个模型。路由优先级：设置 > 会话 > 全局默认。 |
| 思考强度 | 模型默认 | 档位由模型自己公布（DeepSeek 是 `off` / `low` / `high` / `max`）。**选中 `off` 即关闭思考**。 |
| 建议模板 / 润色模板 | 内置默认 | 留空即内置默认。 |
| 草稿上限 / 模板上限 | 8000 / 8000 | 见上节。 |

- 只影响这个按钮，不影响正常对话。
- 两个模式都使用思考强度。选「关闭」就是真的不思考。
- 生成建议的输出上限是 4096 token，润色是 16384 token。`maxTokens` 是上限而非计费。
- 选了模型不支持的档位时不会被拒绝，而是自动退回模型默认。
- 模型不支持调节思考强度时，第二个下拉置灰并说明原因。

设置页的样例草稿、样例用户消息、样例代理回复用于预览与试跑，三段可编辑，两个模式共用，不写入会话。

失败时按钮亮红点，悬停显示错误；详细错误写入 `~/.dsh/storages/prompt-suggest/last-error.json`，包括生成、试跑失败与空输出。试跑的校验类失败（模板不合格、草稿超限）也会落盘，事后能核对当时用的是哪版模板。

生成时会再校验一次已保存的模板：`settings.json` 被手工改坏或来自旧版本时，直接报错而不是把坏模板发出去。这一层的长度按硬上限 32000 判断，不按当前的模板上限——长度在保存时已是不变量，事后调低上限不该让旧模板突然不能用。

## 安装

```
dsh plugin --profile <name> add dsh-prompt-suggest
```

## 测试

```
node --test dsh-prompt-suggest/test/prompt.test.mjs dsh-prompt-suggest/test/settings.test.mjs dsh-prompt-suggest/test/routes.test.mjs
```

`routes.test.mjs` 用假 ctx 接出真实路由 handler，覆盖纯函数测试抓不到的问题：GET 的字段名与前端读取是否对得上、校验类失败有没有落盘、坏模板会不会被发出去。

（Windows 上 `node --test` 不能直接传目录，需列出文件。）
